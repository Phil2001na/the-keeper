Generated by `npx tsx scripts/capability_matrix.ts`. Regenerate it rather than
editing by hand; `--check` exits 1 on any runtime gap and belongs in any CI this

Columns: **defined** = present in `toolDefinitions`; **dispatched** =
`dispatchTool` has a case for it; **in prompt** = the system prompt or the
nightly reflection names it, so the agent knows it exists without being asked.

A row that is defined but not dispatched, or dispatched but not defined, is a
runtime gap: the agent will either be told about a tool it cannot call, or hold
a tool nothing can invoke. That is the exact failure the decision queue shipped
with on 24 Aug 2026 — schema, seeded data, a registered skill and a recurring
touchpoint naming `list_decision_sets`, with no tool behind it.

## Not modelled here

- **Multi-user isolation.** There is one user. `src/db/client.ts` uses the
  service-role key and bypasses RLS by design; no `keeper_*` table has a
  `user_id` column. The boundary that actually exists is set/decision
  resolution, which rejects an unknown key rather than falling through to
  something else. Introducing real tenancy would be a schema-wide change, not a
  decision-queue one.
- **Structured tool results.** `ToolResult` is `{ output: string }` across all
  48 capabilities. The decision tools return formatted, parseable text to match;
  changing the contract would touch every tool and every dispatch case.
